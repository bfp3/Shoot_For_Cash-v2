## Bug 2 — hold-out pineapples freeze the round (critical)

The last session **misimplemented** hold-out pineapples. Current code **breaks ending** and **poisons the next retry**.

### What I actually wanted

Hold-out rounds in `sc/level-beginner.txt` often end with a **pineapple pattern**, e.g. moss:

```
pineapple 5 a5
```

or moss3:

```
pineapple 2 a2
wait 1500
pineapple 4 a4
wait 1500
pineapple 6 a6
```

That pattern is **how pineapples should look** (columns, waits, dual/triple, fanfare). It is **not** something to play in the middle of the hold-out rock loop.

**Correct rules:**

1. During the countdown, play/loop the **rock** script as hold-out always did (`_loop_boss_sequence`). **Do not** freeze because trailing `pineapple` cmds exist. **Do not** jump the cursor to pineapples while the timer is still running.

2. When the **timer hits 0**:
   - Stop feeding rocks. Clear leftover rocks quietly (no strike).
   - Then run the **trailing pineapple sequence** as a real launch: `PineappleLauncher.launch_from_spawn_entry()` so **`_ensure_prelaunch_fanfare()`** still plays (`PerfectPineappleRound` SFX + particles in `ch/Rocks/pineapple_launcher.gd`).
   - Launch the pineapples in script order (respect `wait` stagger between them).
   - After the last pineapple is destroyed / leaves play → `finish_round_after_last_pineapple()` → tally. Stop the timer (already 0).

3. If the player somehow reaches those pineapples **before** the timer (should be rare if they are only started on timeout): shooting them all still ends the round and the timer. Do **not** loop the rock script after that.

4. Hold-outs **with no trailing `pineapple` cmds** keep the old behaviour: timer ends the round (after any live pineapples), rocks loop until then.

5. Abort / backspace / Play again must start the **rock** sequence from the beginning — **never** leftover pineapples.

### What is broken now (fix or replace this)

In `ch/Rocks/rock_manager.gd`:

- `jump_to_trailing_pineapples_if_needed()`, `_trailing_pineapple_start_index()`, `_park_live_rocks_for_pineapple_skip()`, `has_trailing_pineapples()`, `should_end_hold_out_on_pineapples()`.

In `ch/round_manager.gd`:

- `round_timer_time_out()` calls `jump_to_trailing_pineapples_if_needed()` then **returns without `wave_ending`**.
- `check_if_rocks_still_in_air()` / `successful_round()` call `_hold_out_should_finish_on_pineapples()` then `_loop_boss_sequence()`.
- `_loop_boss_sequence()` **returns without looping** if `has_trailing_pineapples()`:

```
if rocks_container.has_trailing_pineapples():
    if try_continue_sequence(): return
    return   # THIS FREEZES THE ROUND
```

That is the freeze: remaining rocks hit 0, hold-out refuses to loop, timer has not expired, pineapples never launch, tally never opens.

Jump path is also wrong for pineapple-only beats: `_begin_beat()` skips `pineapple` (not a launchable rock), `enter_state(PREPARE_ROCKS)` with an **empty rock list**, egg pulse may never happen, so `_run_timed_event_spawns()` never runs `launch_from_spawn_entry` — no fanfare, no pineapples, stuck.

Retry bug: jump/`_cancel_sequence()` leave `_sequence_cursor` on the pineapple block. `_cancel_sequence()` does **not** reset the cursor. Next Play continues from pineapples. After shooting them, hold-out still will not loop / will not tally → stuck again → abort → pineapples again.

`docs/round-loop.md` hold-out bullet currently describes the broken “jump cursor” design — update it to match the timer-then-finale behaviour above.

### Implementation guidance

- Restore hold-out **rock looping** for as long as the timer is running.
- On **timer timeout only**, start a dedicated pineapple finale (do not rely on “skip cursor into the same looping sequence and hope PREPARE/PULSE fires”).
- Prefer collecting trailing `pineapple` (+ inter-pineapple `wait`) entries from the current round’s spawn list, then launching them through `PineappleLauncher.launch_from_spawn_entry` so fanfare always plays. Clear live rocks first. Do not count pineapples as remaining-rocks.
- After finale, `finish_round_after_last_pineapple()` must actually reach `WAVE_END` / tally. Do not leave `wave_ending` stuck false, and do not `_loop_boss_sequence()` after the finale.
- On abort / `reset_all_rocks` / `start_manual_rock_round`, reset cursor **and** `_launched_scripted_pineapple`. Next Play must not start on pineapples.
- `pineapple` mid-script (e.g. moss9 has a pineapple then more rocks) is **not** a trailing finale — ignore those for the timeout finale. Only a **trailing** pineapple block at the end of the round script.
